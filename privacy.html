YouTube Operations

Privacy policy

How the owner-operated upload utility handles Google account, Drive, and YouTube data.

Last updated: 4 October 2026 · Operator: Tweak Relay

1. Scope

This policy covers the YouTube Operations uploader running in the operator’s Google Apps Script project, and this documentation website. The utility uses YouTube API Services and Google Drive. It is currently limited to a designated owner account and channel.

Separate video-production or assistant services are outside this uploader. The uploader itself sends API requests only to Google services and does not send account data to an AI service.

2. Data accessed and purposes

  • Account email: used to check the operator’s identity against the configured account.
  • Drive data: designated folder and file identifiers, file name, media type, size, parent-folder information, and the selected video bytes. These checks identify the intended file and verify its integrity.
  • YouTube data: the authorized channel’s identifier, handle and upload-list reference; recent upload metadata needed to identify an earlier test; and the selected video’s identifier, title, tags, visibility and processing status.
  • Operational records: file references, integrity hashes, upload timestamps, state, and a resumable-upload session reference. These support recovery and help prevent duplicate uploads.

The current Drive permission is read-only and technically covers files available to the authorized account. The utility’s code limits actual reads to its configured folders and designated test video. It does not request Gmail access or Google passwords.

3. Storage and service providers

The source video remains in the owner’s Google Drive. During an upload, Apps Script reads the file and sends its contents and upload metadata to YouTube. The current test upload is private.

Upload-state records are stored in the owner’s Apps Script project properties. Execution logs may contain identifiers, timestamps, results, and error codes. Google manages the authorization flow; the utility does not put authorization tokens or upload-session references in its public reports.

Google processes data as the provider of Apps Script, Drive and YouTube. See the Google Privacy Policy. The operator does not sell Google user data, use it for advertising, or use it to train AI models.

Google API data is used for the authorized upload workflow in accordance with the Google API Services User Data Policy, including its Limited Use requirements.

4. Retention and deletion

Source files and uploaded videos remain under the owner’s control in Drive and YouTube until the owner changes or deletes them there. Removing this tool’s access does not itself delete those original files or uploaded videos.

The setup utility keeps upload-state records to recognize prior attempts. It has no automatic cleanup job. While this setup release is in use, the operator must manually refresh or delete retained YouTube API data within 30 days. Unattended operation requires a tested retention and authorization-check process.

The owner can stop using the utility and remove its stored state from the Apps Script project. Stop pending uploads before removing that state, because it is also used for duplicate prevention. Google service logs follow the applicable Google retention controls.

Requests to delete application-stored personal or API data can be sent through the private contact method below. The operator will process deletion requests as soon as possible and within seven calendar days.

5. Control and revoking access

The owner authorizes Google access and controls which script runs. Access can be revoked at any time from Google account permissions. Revocation prevents future authorized API access; deletion of existing application records is handled separately as described above.

The operator must remove remaining authorized API records within 30 days of Google-side revocation, or within seven days of a direct deletion request. The setup release requires manual administration of this process.

6. Visiting this website

This documentation website contains no sign-in form, advertising, embedded video, analytics tag, or custom tracking cookie. Its public repository contains the documentation files, not the uploader’s credentials or private operational records.

GitHub Pages hosts the site. GitHub records visitor IP addresses for security purposes; its own practices are explained in the GitHub Privacy Statement. Links to other services are governed by those services’ policies.

7. Questions and changes

For private account or data-deletion requests, use the support email displayed on this application’s Google authorization screen. The sole configured user is the operator, who can also manage the application records directly.

For general documentation questions, contact the operator through GitHub Issues. Issues are public: do not include credentials, account email addresses, private files, or private video details.

This policy will be updated before material changes to the utility’s data access or purposes. The owner must review and accept the updated policy before enabling those changes.
